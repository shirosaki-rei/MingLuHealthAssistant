# 2026-10-23

## 明路项目 — UI 按设计稿改造

设计稿：`android/.hbuilderx/uni-agent/design/minglu-miniprogram-ui/`（18 屏小程序原型 + `assets/prototype.css`）。

### 关键决定：设计语言只放一处

全 App 的设计语言（配色/圆角/卡片/按钮/标签/输入框/底部标签栏）收敛到 **`App.uvue` 的全局 `<style>`**，
与设计稿的 `prototype.css` 对齐。页面的 `<style>` 只留「这个页面特有的布局」。
理由：16 个页面各写一套必然漂移，改一处就能全App生效。用脚本按「全局已定义的选择器」
自动删掉页面里的重复规则，共删 186 条。页面里故意覆盖全局的只有两处，都带注释：chat 的 input/btn 定宽、
reminder 的 input 下间距。

### 四项需求落地

1. **出生日期改日期选择器**：`<picker mode="date">` 包一层 view 做触发器，`start="1900-01-01"`、
   `:end` 传今天。空值时 `:value` 传今天，否则原生选择器不认。
2. **监护人开关 × 出生日期算年龄判必填**：`ageOf()` 按完整月日比较（不是只比年份，年内生日没过不算一岁）。
   生日不合法/未填返回 -1，按「未知」处理不拦——只有确凿未满 18 岁才强制，服务端另有兜底。
   界面：日期右侧显示实算年龄，开关行在未成年时亮「必填」标签 + 说明文案。
3. **对话放底部导航栏中间突出显示**：5 格（首页/记录/**问诊**/提醒/就诊人），中间是实心大圆钮。
   用现有页面凑格子，没有新建「我的」页（设计稿有，但用户没要，属范围外）。
4. **「确认病历」→「症状确认」，底部按钮确认后直达匹配科室**：`uni.redirectTo` 到 match 页并把主诉
   带过去（match 页新增 onLoad 读 `options.symptoms` 预填并自动匹配），省得用户再打一遍。

### 新踩到的蒸汽模式坑（已补进 docs/agent/vapor-mode.md）

- **子代选择器 `.a > b` 同样不支持**（原来只记了后代 `.a .b`），且 CLI 只打 ERROR 不说编译失败。
- **负 `margin-top` 会让原生触摸框和视觉位置错位**：圆钮看着在该在的地方，`@tap` 怎么写都没反应，
  不报错。改成让父容器正常变高。
- `<text>` 不支持 `disabled`，可点元素一律用 `<button>` + `@click`。
- 带注释的 CSS 规则在做「按选择器去重」时会被漏掉，脚本要先剥注释再比对。

### 遗留

- 真机验证受限于两点：设备会息屏（息屏后 `input tap` 无声失败），以及设备输入法不吃
  `adb shell input text` 的字母（数字可以，登录就是这么登的）。姓名输入这道校验没能真机走完，
  但代码路径与原版一致、`@input` 机制已在登录页验证。
- 预问诊第 3 步「症状确认」的渲染与「确认 → 匹配科室」跳转只做了编译级验证，没真机走全程。

## 第二轮：按反馈修 UI

### 根因：契约可选字段运行时是 null，生成的类型只标 `?`

用户报「切换时无法选中已有就诊人」。真正原因是 `Patient.birth_date` 服务端返回 **null**，
而 `ageOf()` 只防了 `undefined`，`null.trim()` 抛异常——**uvue 里这会把整个组件更新打断，
界面冻在旧状态、怎么点都没反应**。之前误判成 `Array.find` 闭包失效、reactive 赋值不传播，
全是错的。已加 `android/utils/blank.ts`（hasText/hasList/hasNum）统一判空，
并把 home / patients / chat / report / memory / persona / person 七个页面全换上。
教训：**界面「冻住」先查有没有静默异常，别先怀疑响应式**。

### 其它修复

- **按钮文字偏下**：`.btn` 上写 `line-height: 88rpx` 会和原生 button 自带的垂直居中叠加。
  去掉 line-height，改用 `align-items/justify-content: center`。
- **头像偏左**：`<text>` 不是 flex 容器，要 `text-align: center` + 等高 `line-height` 才居中。
- **`v-if` 在 `<picker>` 上不生效**：包一层 `<view v-if>` 再放 picker。
- **`initAuth()` 只恢复 token 不恢复 user**：重启后首页问候语/手机号退化成兜底文案。
  user 一起存 `minglu.user`。
- **首页「切换」** 原来跳管理页，改成 `<picker mode="selector">` 直接选人。
- 新建 `pages/person/person.uvue`（设计稿的「我的」聚合页），底部标签栏最后一项改为「我的」，
  退出登录从首页挪过去。
- 提醒页：触发时间改「日期 picker + 时间 picker」拼 ISO 8601（时区从设备取），
  重复改胶囊（一次/每日/每周/自定义），每周再选星期，自定义才显示规则输入框；
  内容框标签按类型变（选「自定义」就是普通提醒内容）。

### 设备调试两个坑

- **设备息屏后 `adb shell input tap` 全部无声失败**，不报错，只是没反应。
- **这台设备的输入法不吃 `adb shell input text` 的字母**（数字可以）。
  所以需要输中文/字母的表单没法用 adb 跑通，只能编译级验证。

## 第三轮：再修一轮反馈

### 新根因：只包一个 `<text>` 的 view 收不到点击

提醒页的重复胶囊、就诊人页的关系胶囊，写了 `<view class="chipItem" @tap="...">` 包一个带背景的
`<text>`，**点了没反应且不报错**。原因是 `<text>` 带背景色时渲染成原生 TextView，
点它不往父 view 冒泡，而父 view 自身没背景也没尺寸，触摸框是空的。
底部标签栏和首页宫格能点，是因为那两处 view 有 `flex:1` / `width:25%`。
**改成 `<button>` + `@click` 立刻好**，已把胶囊类按钮全换掉。

### 按钮文字偏下的根因

`.btn` 上写 `line-height: 88rpx`，会和原生 button 自带的垂直居中叠加，把文字压到偏下。
去掉 line-height，改用 `align-items/justify-content: center`。头像偏左同理：
`<text>` 不是 flex 容器，要 `text-align: center` + 等高 line-height。

### 一个诚实的教训

前面几轮我把「界面冻住」误判成 `Array.find` 闭包失效、reactive 赋值不传播，全是错的。
真正原因一直是 `null.trim()` 抛异常打断渲染。**先查静默异常，别先怀疑响应式**——
临时在模板里打一行 `{{ 变量 }}` 比读代码猜快得多。
