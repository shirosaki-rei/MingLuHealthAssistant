### 第一期：切页丢消息 / 切换就诊人 / 开新对话 / 免责降频 / 思考模型
- **切页后消息空**：标签页之间是 reLaunch，每跳一次页面整个重建，`msgs` 回到空，
  而原来只有发一句话后 `onDone` 才拉全量 → 表现是「切走再回来一片空白，发一句话才全冒出来」。
  修法：`onPageShow` 里补 `loadHistory`。
- **切换就诊人**：`session` 加 `conversationPatientId` 记会话归属，对话页每次显示时比对，
  换过人就丢旧会话。不能用页面级变量比（reLaunch 会重建页面，本地变量记不住上次是谁）。
- **「开新对话」**：三个点菜单置顶，清 `conversationId`，旧消息不删不隐藏
  （`hidden` 字段和归档列表是第三期）。
- **免责降频**：SAFETY_PROMPT 第 7 条改成「首次或给建议时带一句，不要每轮重复」；
  本地模板兜底里那句固定免责删掉。保留两处真兜底：模型全挂的降级回复、内容被安全过滤干净时。
  用户依据：输入框上方已有常驻边界声明。
- **安全约束第 5 条放宽**：原来「涉及症状、指标、用药时语气中性」等于全程中性
  （用户问的都是症状）。改成「医学内容严谨中性，其他内容不受限」。
- **思考模型支持**：`OpenAICompatProvider` 只取 `content`，`reasoning_content` 不取也不展示；
  content 为空时抛错走降级（思考模型把 max_tokens 花在推理上就会这样，原来会返回空文本
  让用户看到空白气泡）。`max_tokens` 800 → 2000（上限值，非思考模型费用不受影响）。

### 第二期：语义记忆（LLM 总结式抽取）
- `_extract_memories` 的关键词匹配（只认"过敏/高血压/糖尿病"三个词，value 是原话截断）
  换成 LLM 总结抽取：输出 `{"facts":[{"key":..,"value":..}]}`。
- **key 用固定 8 类**（medication/symptom/allergy/chronic/check/plan/habit/emotion）：
  `remember()` 按 (user, patient, key) 去重，自由 key 会无限膨胀、同义不同名。
- **异步线程**：抽取是一次额外 LLM 调用（1~3 秒），同步做会把 done 拖后。
  线程里自己开 session（ORM 对象不能跨线程传，SQLAlchemy session 也不是线程安全的）。
  失败只记日志——记忆是增强不是主链路。
- **confirmed=True**：抽的是用户自己说出的事实、不是推断，记忆页可逐条删除兜底。
  要等用户确认才生效的话，抽了也白抽（没人会专门去记忆页点确认）。
- **实测通过**：用户说"最近在吃氨氯地平 5mg"→ 记忆写入；下一轮不提药名问
  "我在吃的药方面要注意什么" → 助手开口就是"关于您正在服用的氨氯地平"。
- prompt 里加了「用户说没有/不/没时不要抽」：负向信息没有记忆价值，
  会产出 `chronic = 没有` 这种废话条目还占记忆条数。
- 已知局限：`glm-4-flash` 抽取不完整（"打算下周做胃镜"这类 plan 没抽到），换 glm-4-plus 会好。

## 明路 — glm-5.3-flash 接入与思考档位（2026-11-02 晚）

用户把模型换成 `glm-5.3-flash`，实测发现几个关键点：

- **它是"始终思考"模型**：`thinking: {"type":"disabled"}` 会被拒（错误码 1210：
  「该模型始终思考，不支持关闭思考；请使用 low、high 或 max」）。
  有效的开关是 **`reasoning_effort`**：`"low"` 让 reasoning 归零，
  `{"type":"low"}` / `"thinking":"low"` / `{"budget":"low"}` 都是无效格式。
- **默认档（思考全开）又慢又客服**：完整链路 22 秒，输出是"一般来说，偶尔几晚没睡好，
  可以先试试把作息调规律…"这种标准客服腔。思考预算花在"如何不越界"上，人设被压掉了。
- **`low` 档又快又有陪伴感**：完整链路 10 秒，输出"辛苦了，睡不好还硬撑着，
  整个人像被抽空一样吧，抱抱你。想跟你多聊几句吗？…"。reasoning 0 字。
- 抽取能力也更强：`plan = 下周去做胃镜` 稳定抽到（glm-4-flash 抽不到）。

### 落地
- `LLM_REASONING_EFFORT` 配置项（默认空 = 不传）：非思考模型传 `reasoning_effort`
  有被拒风险，所以不能写死，由使用者按模型设置。`.env` 已设 `low`。
- 记忆抽取改为**不传 `max_tokens`**：思考模型推理长度不可预测（同一条输入实测从几百到
  四千 token 波动），写死额度（300、1000 都试过）会随机把正文挤成空 content。
  `complete()` 的 `max_tokens` 因此改成可选，None 时不传该字段。

### 仍待解决
- **10 秒延迟**：`complete()` 是非流式（`stream: False`），要等全文生成完才按句推 SSE，
  用户盯着"正在输入…"约 10 秒。要降到 1-2 秒首字得改真流式（provider 协议改生成器 +
  按句缓冲重排 + 跳过 reasoning_content），改造成本不低，暂缓。

## 真流式改造（先实测再动手，省掉一次负优化）

原本要"把非流式改流式降首字延迟"，先写探针测了一遍才发现前提是错的：

- `reasoning_tokens=0`：`reasoning_effort=low` 下 glm-5.3-flash **根本不思考**，
  10 秒不是推理占用。
- 477 字的生成本身只占 0.8 秒，其余全是**首 token 等待**（厂商排队/预填充）。
- 流式实测首字甚至更晚（14.58s vs 非流式 9.48s）——单次测量有噪声，但足以说明
  「流式 ≠ 首字更快」。

所以改造目标从"降首字"改成"首字之后按句流出"：响应头 3.8s、首字 5.4s、
380 字按 12 个 delta 在 4.9s 内流完（改前是干等 9.5s 一次性给全文）。

实现上两个决定：
- **增量切分直接复用 `safety.iter_sentences`**，没自己写缓冲区。它没碰到句末标点时
  返回 `([], 原样剩余)`，天然就是"只吐已确定的完整句子"——SSE「一个 delta 至少是
  完整句子」的契约因此自动成立，`postcheck` 逐句校验的位置也不用动。
- **tokens 改估算、model 记 provider 上的真实模型名**：流式没有 usage，
  但 ai_log 的成本核算不能因为改了流式就归零。latency_ms 语义顺带变成"首 token 延迟"，
  这比"总耗时"更有分析价值。
- 读超时 30s → 90s：首 token 实测能到 20s+，30s 会在长 prompt 上随机 ReadTimeout，
  而那时降级出去用户只看到模板兜底，很难反查。

## 真机通道：电脑连手机热点时用 adb reverse

电脑一直连的是**手机热点**，所以之前 ping 不通不是网络故障——热点的客户端隔离
会挡掉电脑 IP，电脑 ARP 里也看不到手机。局域网 IP 那条路走不通，别在上面耗。

解法是绕开二层：`adb reverse tcp:8000 tcp:8000` + `BASE_URL` 填 `http://127.0.0.1:8000`。
每次插线后要重跑一次 reverse。验收标准是**手机侧带认证的请求返回 200**
（`adb shell curl -H 'Authorization: Bearer …' http://127.0.0.1:8000/v1/patients`），
只 curl `/docs` 不够——那只证明静态路径通。

顺带几条 adb 经验：
- **坐标必须 PIL 量**。这次连点两次"问助手"没反应，肉眼估的 y 偏了 58px 点到圆钮外面。
  量 brand 色像素团中心，两次都一发命中。
- **`adb input text` 不吃中文**（Android 服务端 sendText 的限制，不是 shell 编码问题，
  python subprocess 直接传参一样 NPE）。要中文输入得装 ADBKeyboard，没装就用英文验流式
  ——SSE 逐句渲染与语言无关。
- **键盘弹出时点的坐标会错位**。第一次发消息点在了键盘上，只收起键盘没发出去。
- Git Bash 会吞 `/sdcard/...` 参数，`screencap` 直接打印 usage，加 `MSYS_NO_PATHCONV=1`。
- HBuilderX 被回收后要先 `cli open --path <项目>`，直接 launch 会报「未检测到已打开的HBuilderX」。
