## 〇、演示前 5 分钟准备

### 1. 重置数据库（让新数据生效）

种子数据只在空库时写入。旧的 `minglu.db` 里还是老的 10 位医生、5 条知识，必须先删：

```bat
:: 先停掉后端，否则文件被占用删不掉
cd F:\hongmeng\pj1\services\api
del minglu.db
```

### 2. 启动后端

```bat
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`--host 0.0.0.0` 不能省，否则手机连不上。

### 3. 灌演示数据

另开一个终端：

```bat
cd F:\hongmeng\pj1\services\api
.venv\Scripts\python.exe scripts\demo_seed.py
```

跑完会打印：

```

验证码：580834（5 分钟内有效）
```

**把这两行记在纸上或手机备忘录里**，演示时直接用。验证码 5 分钟过期，快轮到你再跑一次。

### 4. 确认前端地址

```ts
// android/api/http.ts
export const BASE_URL = 'http://10.43.253.140:8000'
```

这个 IP **换 Wi-Fi 就会变**，每次演示前用 `ipconfig` 确认一次。

### 5. 手机准备

- 与电脑连同一个 Wi-Fi
- 关掉移动数据（有时会优先走 4G）
- 亮度调到最高，开勿扰

## 二、90 秒版

**不用打开 App**，拿手机讲：

> 现在人生病了，第一反应是搜索。但搜出来的是疾病清单，不是你该怎么办。
>
> 我们做的事很简单：**先问清楚，再告诉你该找谁，最后把你送到对的医生面前。**
>
> 不诊断、不开方、不卖药。AI 永远不说"你得的是某某病"，它只做两件事——把模糊的描述问清楚，以及告诉你该挂哪个科、为什么。

如果对方有兴趣，做**一个动作**：

打开 App → 输入「我妈最近站起来就头晕」→ 等回答出来，指一句：

> 注意这里有来源和更新时间。我们不编答案。

## 三、标准版（5 分钟）

### 第 1 步：登录（20 秒）

输入手机号和验证码（脚本打印的）。

> 手机号登录，不采集身份证、不要通讯录。健康数据只存在我们自己境内服务器。

### 第 2 步：对话（60 秒）

点「对话」，输入：

```
我妈最近总说站起来头晕，量了血压也偏低，需要去医院吗？
```

**讲解词**（等回答出来的同时说）：

> 回答里有两个细节值得看。第一，它带了来源和更新时间，不是模型凭空编的。第二，它主动给了「就医指征」——什么情况下必须去医院。这是我们的安全基线：宁可多说一句"该去看医生"，也不给一个让人放心的错误答案。

**不要**在这一步停留太久，重点是下一步。

### 第 3 步：预问诊（90 秒）★核心

点「预问诊」，主诉填：

```
反复头晕两周，起身时明显
```

然后**快速点几轮选项**，每轮只念一句：

> 它不是直接给结论，而是一轮一轮问：什么时候开始的、什么情况下加重、有没有伴随症状。六轮之内，把一句"我头晕"变成一份结构化的病历。

六轮结束，病历生成。指着屏幕：

> 这份病历可以直接给医生看。这就是我们和"聊天机器人"的区别——它有终点，产出是能用的东西。

### 第 4 步：科室匹配（30 秒）

点「找医生」：

> 它给了神经内科，置信度 0.99，而且写了为什么——"症状描述与神经内科的常见主诉吻合"。**我们不只给结果，给的是可解释的结果。** 这一点市面上很少见。

### 第 5 步：医生与下单（60 秒）

点进医生列表，指着一个医生：

> 每个医生都标了响应时间和评分。选一个，下单。

下单，支付（**演示环境是模拟支付**，如实说明）。

> 支付这块现在是模拟的，正式接微信支付。

### 第 6 步：收尾（20 秒）

回首页 → 健康 → 时间线。

> 刚才那次咨询、那份病历，都进了时间线。下次复诊，医生能看到完整的记录，而不是听患者回忆。

## 四、完整版再加三段

### 4.1 红线演示（最有说服力，务必演）

在对话里输入：

```
我胸口疼得厉害，喘不上气，冷汗直流
```

**App 会立刻弹出急救卡片，不再继续生成回答。**

讲解词：

> 这一步是产品的生死线。它没有先问"你多大年纪、有没有高血压"，而是直接告诉你：这可能是心脏急症，立刻打 120。
>
> 因为胸痛伴冷汗、呼吸困难，是必须争分夺秒的情况。**在这种时候，多问一句都是错的。**
>
> 这套判断不依赖大模型——它是纯规则，写在代码里。模型挂了，这一层照常工作。

再补一句对比（可选，很有力）：

```
我这两天有点头晕
```

> 普通的头晕，它不会误报。这是我们反复调的地方：**宁可少拦，不能乱拦**。乱拦会让人对警告麻木。

### 4.2 提醒（60 秒）

点「提醒」：

> 用药提醒是 App 独占的能力。小程序做不到——它没有系统级的精确闹钟。
>
> 所以我们把提醒放在 App 里，而且是**精确到分钟**的：到点就响，息屏也响，重启手机后还能恢复。这一条我们专门做了原生插件验证。

### 4.3 会员与红线（30 秒）

点「我的」→ 会员。

> 会员卖的是「管全家」——多个人档案、报告沉淀、时间线。不是卖皮肤。
>
> 但有一件事我们永远不收费：**预问诊、找科室、找医生、下单，以及急救提醒，全部免费。**
>
> 不付费的人也能完整走完就医流程。这是产品底线，写进了代码里，不是靠自觉。

## 五、五个必须讲到的差异点

别人会问"你和 XX 有什么区别"，准备好这五条：

| # | 差异 | 一句话 |
|---|---|---|
| 1 | **可解释的匹配** | 不只给科室，给"为什么是这个科室" |
| 2 | **可溯源的答案** | 每条回答带来源和更新时间，过期内容自动下线 |
| 3 | **家庭档案** | 一个人管父母孩子，这是订阅的真实理由 |
| 4 | **提醒是 App 独占** | 小程序碰不到系统闹钟，这是我们做 App 的原因 |
| 5 | **付费墙不拦就医** | 不付费也能看医生，红线写死在服务端 |

第 5 条最容易被追问，主动讲出来会加分。

## 六、可能被问到的问题

| 问题 | 怎么答 |
|---|---|
| 出了医疗事故谁负责 | 我们不诊断、不开方。产品定位是科普与咨询撮合，医生回复由医生负责。全过程留痕，可追溯 |
| AI 说错了怎么办 | 三层防护：回答必须带来源；输出有禁用词与边界校验；红旗用纯规则不依赖模型。另外有"这是 AI 生成，不能替代面诊"的强制标识 |
| 数据合规吗 | 境内存储，模型服务商也在境内，白名单写死。手机号加密，支持删除账号 |
| 医生从哪来 | 冷启动靠单场景切入（慢病 + 报告解读），医生个人品牌页 + 前期补贴。这块是我们最重的运营工作 |
| 怎么赚钱 | 会员（管全家）+ 咨询抽成 + 企业健康福利。首年按打平测算，赚钱靠规模 |
| 大厂做了怎么办 | 大厂的强项是入口和供给，弱项是"连续的人"。我们的壁垒是档案积累 + 医生密度，不是单点功能 |
| 为什么不做 iOS | 现阶段资源有限，先做安卓和小程序验证。iOS 用户的付费能力更强，是二期的事 |
| 为什么用 uni-app x | 一套代码出三端，四个人能在 14 周交付。这一点我们做过 PoC 验证，不是拍脑袋 |
| 模型用的哪家 | 境内服务商，可切换。我们做了网关层，换模型不用改业务代码 |
| 现在到什么程度 | 后端 37 个接口全部实现并有测试；前端 18 个页面；演示链路完整。缺的是知识库规模、医生签约和合规备案 |

**"现在到什么程度"这题一定要如实答**。夸大一次，后面全崩。

## 十、演示脚本之外的一句实话

如果评委问"这个东西最难的是什么"，别答技术。

答：**最难的是让人相信一个 AI 不会害他。** 所以我们把钱花在了三件不显眼的事上——每条答案带来源、红旗不依赖模型、不付费也能看病。这三件事都不产生收入，但少了任何一件，这个产品就不该存在。
