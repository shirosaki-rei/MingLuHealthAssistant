# 明路 PoC · 精确闹钟测试步骤

> 对应验证项：PoC 方案 §4.4  
> 插件位置：`uni-appX/uni_modules/minglu-alarm`  
> 测试页：`uni-appX/pages/alarm/alarm.uvue`

---

## 为什么必须做「自定义基座」

这个插件里有 `MingluAlarm.kt` 原生代码，还往 AndroidManifest 里注册了两个 BroadcastReceiver。

**HBuilderX 默认用的「标准基座」是官方预编译好的安装包，里面没有你的原生代码**，直接运行只会得到「插件不存在」或方法找不到。

所以必须打一次自定义基座。这一步和云打包是同一个流程，只是产物是调试用的。

---

## 第一步：制作自定义基座

1. HBuilderX 登录 DCloud 账号（没有就注册，免费）
2. 菜单：**运行 → 运行到手机或模拟器 → 制作自定义调试基座**
   - 旧版本在：发行 → 原生 App-云打包 → 勾选「打自定义调试基座」
3. 选择 Android，等待云打包（约 3~8 分钟）
4. 完成后，运行菜单里会出现「使用自定义基座运行」，选中它

> 打一次就行。之后改 JS/页面代码不用重打，**只有改了 Kotlin 或 AndroidManifest 才需要重打**。



---

## 第二步：跑起来看权限

运行到手机 → 首页点「去验证精确闹钟」。

页面顶部会显示「已授权 / 未授权」。

- **已授权** → 直接进第三步
- **未授权** → 点「去系统设置授权」，在系统页面里找「闹钟和提醒」或「特殊应用权限」，允许明路使用精确闹钟

Android 12 以下没有这个开关，会直接显示已授权。

---

## 第三步：三项验证

### 3.1 准时性（必测）

1. 点「60 秒」
2. 立刻锁屏，把手机放桌上不要动
3. 等 60 秒

**通过标准**：60 秒到点时收到通知，误差 <10 秒。

> 如果手机设了「勿扰模式」，通知可能被静音但仍然会到达。看通知栏有没有。

### 3.2 长时延（必测）

1. 点「8 小时」
2. 正常使用手机，或者放一夜
3. 第二天看有没有收到

**通过标准**：误差 <1 分钟。

这一项才是真考验——短时延靠内存里的定时器也能糊过去，8 小时必须依赖 `setExactAndAllowWhileIdle` 穿透 Doze。

### 3.3 重启恢复（必测）

1. 先点「30 分」
2. **重启手机**
3. 不要再打开 App，等 30 分钟

**通过标准**：能收到通知。

这一项验证 `MingluBootReceiver` + `BOOT_COMPLETED` 是否生效。如果收不到，多半是自启动权限被 ROM 拦了。

---

## 第四步：国产 ROM 适配

小米 / 华为 / OPPO / vivo 会主动杀后台，需要用户手动放行。提前记录每台机器要开哪些开关：

| ROM       | 要开的东西                 | 位置                        |
| --------- | --------------------- | ------------------------- |
| 小米 / 红米   | 自启动、省电策略设为「无限制」、通知权限  | 设置 → 应用 → 明路 → 自启动 / 省电策略 |
| 华为 / 荣耀   | 应用启动管理改为「手动管理」，三个开关全开 | 设置 → 应用启动管理               |
| OPPO / 一加 | 允许自启动、允许后台运行、关闭智能省电   | 设置 → 电池 → 应用速冻            |
| vivo      | 允许后台高耗电、自启动           | 设置 → 电池 → 后台耗电管理          |

> 这些开关不是代码能绕过的，必须做成引导页。这也是为什么 PRD 里把「提醒」定为 App 独占能力——小程序根本碰不到这一层。

## 判定与降级

| 结果          | 处置                                                   |
| ----------- | ---------------------------------------------------- |
| 三项全过        | 精确闹钟通过，PoC 收尾，可以进入架构设计                               |
| 短时延过、8 小时不过 | 检查电池优化白名单；仍不过则降级为 `setWindow`（±15 分钟），并在 UI 说明       |
| 重启后不恢复      | 检查 `BOOT_COMPLETED` 是否被 ROM 拦；补一个「打开 App 时重排全部提醒」的兜底 |
| 自定义基座打不出来   | 这是流程问题不是技术问题，找 DCloud 账号或网络问题                        |
| Kotlin 编译报错 | 把完整报错发我，多半是 UTS 与 Kotlin 的类型签名对不上                    |

## 已知风险

| 风险                                     | 说明                                                                                                                     |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| UTS 导入 Kotlin object 的写法               | 用的是 `import { MingluAlarm } from 'com.minglu.alarm'`，若编译报「找不到符号」，改成 `import { MingluAlarm } from './MingluAlarm.kt'` 试 |
| `UTSAndroid.getAppContext()` 可能返回 null | 已用 `as Context` 断言，若运行时空指针，改成在 `setExact` 里接 context 参数                                                                |
| 通知图标                                   | 用的是系统图标 `android.R.drawable.ic_dialog_info`，正式版要换成自己的小图标，否则部分 ROM 显示空白                                                 |
| 精度承诺                                   | Android 的精确闹钟仍可能被极端省电模式推迟几十秒，产品文案不要写「准点」                                                                               |
