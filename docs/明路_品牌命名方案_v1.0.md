# 明路 · 品牌命名方案（V1.0）

> 配套文档：《日常健康助手 PRD v3.1》
> 适用范围：App、小程序、公众号、医生端、运营后台、对外物料
> 编写日期：2026-10-21
> 说明：本方案以「明路」为主推名。若最终换名，只需替换品牌名，**三层架构与命名规则不变**。

---

## 1. 一句话结论

| 项 | 内容 |
|---|---|
| 产品名 | **明路** |
| 副标题 | 健康的事，先问清楚，再找对人 |
| 主 Slogan | **身体有事，先问明路** |
| 英文 | 不做英文名，对外用拼音 Minglu |
| 品牌隐喻 | 路径、方向、晨光、门 |
| 主视觉人格 | 安安（唯一对外形象） |

## 2. 三层品牌架构（核心）

名字乱，通常不是名字不好，是层级没分开。本产品必须严格区分三层：

| 层 | 是什么 | 命名 | 使用场景 |
|---|---|---|---|
| **L1 平台层** | "场所" | 明路 | App 图标、小程序、公众号、商店页、官网 |
| **L2 角色层** | 场所里的"人" | 安安 / 小简 / 老陈 / 小叶 | 对话界面、角色中心、宣传语中的"谁在帮你" |
| **L3 功能层** | 场所里能做的"事" | 预问诊 / 找医生 / 时间线 / 就诊摘要 | 导航、按钮、功能入口 |

**用户语言应该长这样：**

> "我在**明路**上问**安安**，她帮我把症状问清楚了，然后带我去找张医生。"

而不是：

> "我用的那个 AI 健康助手叫明路，里面有个 AI 叫安安。"（两层，听的人会懵）

### 三层各自的铁律

| 层 | 可以 | 不可以 |
|---|---|---|
| L1 平台层 | 做人格化联想（"明路"有方向感） | **不叫"小明""小安"**，会与角色抢位 |
| L2 角色层 | 有名字、有性格、可自定义 | **不加产品名前缀**（不叫"明路安安"） |
| L3 功能层 | 直白、可搜索、可翻译 | **不做子品牌**（不叫"明路问诊""明路医典"） |

---

## 3. 副标题与 Slogan 体系

### 3.1 副标题（商店页 / 小程序简介 / 官网首屏）

主：**明路 —— 健康的事，先问清楚，再找对人**

备选（更短，用于小程序 120 字简介开头）：
- 说不清的症状，它帮你问清楚
- 帮你找到对的医生，而不是一堆医生

### 3.2 分场景 Slogan

| 场景 | 文案 | 说明 |
|---|---|---|
| 通用 / 拉新 | 身体有事，先问明路 | 主 Slogan，含品牌名，6 字好记 |
| App 首屏 | 说不清的症状，它帮你问清楚 | 对应预问诊，是产品最独特的动作 |
| 代问诊 | 替爸妈问，也能问明白 | 对应多档案，切中付费意愿最强的人群 |
| 报告解读 | 箭头是什么意思，讲人话 | 对应报告解读，天然传播点 |
| 就诊摘要 | 把线上问过的，变成医生看得懂的 | 对应时间线导出，B 端与医生获客入口 |
| 医生端 | 30 秒读懂病情 | 对应结构化病历，医生侧价值主张 |
| B 端 | 员工健康的第一道门 | 企业采购话术，强调"门"而非"医院" |

### 3.3 明确不用的表达

| 类型 | 例子 | 为什么不用 |
|---|---|---|
| 医疗承诺 | 守护您的健康 / 让疾病远离 | 暗示疗效，合规风险 |
| 空话 | 健康同行 / 智慧医疗 / 一站式 | 没有信息量，谁都能说 |
| AI 炫耀 | 大模型驱动 / 智能诊断 | "诊断"直接越界 |
| 拟人过度 | 你的 AI 家人 / 永远陪着你 | 与 §13.3 情感依赖管控冲突 |

## 4. 命名规则（防止品牌被稀释）

| # | 规则 | 理由 |
|---|---|---|
| 1 | 产品名后不加"健康""医疗""科技" | "明路健康"退回通用词，商标更难，也弱化差异化 |
| 2 | 角色名前不加产品名 | 角色是"人"，不是"产品功能" |
| 3 | 功能名不含品牌词 | 一旦出现"明路问诊""明路医典"，就会长出十个子品牌 |
| 4 | 对外统一称"健康助手"，不称"AI 医生" | 合规底线，见 PRD §1.3 |
| 5 | 不做英文自造名 | 无海外计划，自造词只增加商标与传播成本 |

## 5. 端命名差异

| 端 | 展示名 | 原因 |
|---|---|---|
| App（桌面图标） | 明路 | 主品牌，越短越好 |
| 安卓应用商店标题 | 明路 - 健康问题先问清楚 | 商店标题带搜索词权重；华为/小米/OPPO/vivo/应用宝需分别提交 |
| 小程序 | **明路健康助手** | 小程序需覆盖"健康助手"这个高频搜索词，且名称唯一性更容易过 |
| 小程序（分享卡片标题） | 明路 | 卡片空间小，只留品牌名 |
| 公众号 | 明路健康 | 承接服务通知与内容，不带"助手"避免与小程序重名 |
| 医生端 H5 | 明路 · 医生工作台 | 明确身份，防止医生误入患者端 |
| 运营后台 | 明路运营后台 | 内部使用，无需品牌化 |

**注意**：小程序名 6 字符合 2~20 字规则；"健康助手"为通用描述词，需在微信公众平台查重后再定。

## 6. 角色与品牌的关系：一个主形象 + 三个场景推荐

四个角色不能平权，否则用户记不住，视觉上也没有单一符号。

| 角色 | 品牌角色 | 出场位置 |
|---|---|---|
| **安安** | **品牌主形象（唯一对外）** | 启动页、商店截图、宣传图、新用户默认人格 |
| 小简 | 场景推荐 | 上传报告后推荐切换 / 报告解读页引导 |
| 老陈 | 场景推荐 | 建立慢病档案或连续打卡后推荐切换 |
| 小叶 | 场景推荐 | 情绪相关话题连续 3 轮后温和提示"要不要换个说话方式" |

**规则**：

1. 所有对外物料只用安安，不出现四人合影——四个形象同时出现会让品牌失去焦点
2. 产品内四个角色平权可选，不设"推荐位"以外的优先级
3. 角色改名（用户自定义）不影响品牌层，品牌永远叫明路

## 7. 视觉与语言调性

### 7.1 视觉隐喻

| 用 | 不用 |
|---|---|
| 路径、台阶、门、罗盘、晨光 | 十字、听诊器、白大褂、心电图、胶囊 |
| 留白多、字重轻 | 密集信息、饱和撞色 |

理由：一旦出现医疗符号，产品会被默认理解成"网上看病"，与"非诊疗"定位冲突。

### 7.2 配色建议

| 角色 | 色值 | 说明 |
|---|---|---|
| 主色 | 墨绿 `#2F4F43` | 沉静、可信，避开被大厂占满的医疗蓝 |
| 底色 | 暖砂 `#E8DCC8` | 有纸张与温度感，区别于冷白底的健康类产品 |
| 强调 | 晨光橙 `#E08A3C` | 对应"明路"的光感，用于关键行动按钮 |
| 危险 | `#C0392B` | 红旗与异常指标专用，不参与品牌表达 |

> 趋势图沿用中文习惯：超标标红，见 PRD §8.3。

### 7.3 语言调性

| 场景 | 说法 |
|---|---|
| 称呼用户 | "你"，不用"您"（避免医患距离感） |
| 涉及风险 | 去掉所有修饰，直述动作（"现在拨打 120"） |
| 涉及不确定 | 说"需要医生判断"，不说"应该没事" |
| 涉及边界 | 说"我不能替代医生"，不说"仅供参考"（后者太轻） |

## 8. 定名前必须查的四件事

| # | 项 | 具体 |
|---|---|---|
| 1 | 商标 | 第 9 类（软件）、35 类（广告销售）、42 类（技术服务）、44 类（医疗健康服务） |
| 2 | 小程序 | 微信公众平台搜索"明路健康助手"是否重名；同名则改用"明路健康"或"明路助手" |
| 3 | 公众号 / 域名 | 公众号"明路健康"是否可申；minglu.com/.cn 是否可注册 |
| 4 | 应用商店 | App Store 与主流安卓商店是否有同名健康类应用 |

**若"明路"商标被占**，按顺序退：安常 → 看哪 → 起居。三者均已在上一轮评估过，架构同样适用。

## 9. 不建议使用的名字（黑名单）

| 类型 | 例子 | 原因 |
|---|---|---|
| 含医疗字样 | 明医、诊路、药明 | 备案与类目审核会被质疑超范围；"药明"另有知名企业 |
| 拟人化小名 | 小明、小安、康康 | 与角色层抢位，用户分不清谁是产品谁是助手 |
| 状态断言 | 无恙、安康、保康 | "无恙"字面即"没有病"，构成健康承诺 |
| 已被占用 | 晓医、小荷、妙健康、丁香、春雨、平安健康 | 直接撞车 |
| 通用词 | 健康助手、AI 健康、智慧医疗 | 无法注册，也无法记忆 |
