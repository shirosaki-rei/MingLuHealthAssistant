# 明路 · 简历项目段（参考精斗云版式）

**明路 — AI 健康助手（三端同源）**　　　　　　　　　　　　　　2026.10 — 至今

安卓 / 微信小程序 / H5 全栈开发 · 架构设计 · 接口契约

面向普通人的健康咨询产品（非诊疗，不诊断不开方），解决"不知道挂什么科、搜索只有病名没有决策、找医生门槛高"。主导架构设计与接口契约，落地三端 19 个页面与 13 模块后端；以 OpenAPI 契约为唯一真相源驱动前后端并行开发，移动端与小程序共用一套 API 层。

uni-app x（UTS / 蒸汽模式）· FastAPI · PostgreSQL · Redis · SSE · OpenAPI 3.1 · Docker

- **契约先行消除联调返工**：以 `openapi.yaml` 为唯一真相源，双向生成前端 TS 类型与后端 Pydantic 模型，39 个 operation、23 个错误码全部有实现；契约测试断言白名单清单与代码逐条一致，接口从 v1.0 演进到 v1.3 的变更全部靠重新生成消化，不手工对齐。
- **蒸汽模式适配：5 类静默失效无报错**：新版渲染模式下事件绑定写赋值表达式、动态 `:class` 选中态、`ref` 深层修改、后代选择器、`display` 取值均静默失效（不报错、不警告）。真机逐条复现后沉淀为 15 条硬约束写入仓库规范，后续 19 个页面零重复踩坑。
- **SSE 流式跨端方案**：小程序与 App 端缺 `TextDecoder`，手写 UTF-8 分块解码 + `enableChunked` 逐块解析；服务端按句缓冲推送，使"逐句后置校验"能生效——用户看不到未校验文本，首字延迟仍控制在 2s 预算内，三端共用同一套事件协议（`delta` / `redflag` / `done`）。
- **AI 安全层不依赖模型**：232 行纯规则引擎承担红旗症状拦截（11 条）、输入注入检测与逐句输出校验，与 LLM 调用解耦，模型全挂时急救引导仍可触发；配 3 道机制保障就医路径永不设付费墙（31 条 action 白名单 + 路由装饰器兜底 + 契约测试断言误拦为 0）。
- **模块化单体的边界治理**：13 个业务模块 + 独立 platform 层，用 `import-linter` 静态断言"模块间只能走 service 层、safety 不得依赖 llm_gateway"，违反即 CI 失败；34 项测试覆盖主链路、契约一致性与架构依赖规则，全部通过。
