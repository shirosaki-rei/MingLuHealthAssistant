## 二、后端：两条命令

```bash
cd services/api

# 首次（或加了新依赖后）
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 单元/集成测试
.venv\Scripts\python.exe -m pytest -q
# 期望：43 passed
```

> **必须用 `.venv` 的解释器**。系统 python 会 `ModuleNotFoundError: sqladmin`
> ——`app/main.py` 挂了运营后台（`/admin`），它的依赖只在 venv 里装过。
> CI 那边是 `pip install -r requirements.txt` 后用系统 python，所以两边一致。

### 写测试的两条硬规矩

**1. 测试不许连真实模型。** `tests/conftest.py` 强制 `LLM_BASE_URL=""`，全部走
`LocalProvider`（模板兜底）。原因不只是慢和花钱——真实模型的输出不稳定
（markdown 标记、句式长短）会让「一个 delta 至少是完整句子」这类断言随机失败。

**2. 时间不许写死。** 提醒的 `fire_at` 必须晚于当前时间，硬编码日期会随现实时间过期
（`2026-11-01` 就刚让一条用例红得很莫名）。用 conftest 里的 helper：

```python
"fire_at": _future(30, 9)          # 30 天后的 09:00，ISO 8601 带 +08:00
"fire_at": _future(30, 23, 30)     # 30 天后的 23:30
```

## 五、真机联调的拦路虎

### 网络三个（老问题，按序排查）

| 现象            | 原因                   | 解法                                                                  |
| ------------- | -------------------- | ------------------------------------------------------------------- |
| 请求超时 / 连接被拒   | 手机和电脑不在同一网段          | 都连同一个 Wi-Fi，关掉手机流量                                                  |
| 浏览器能开、App 打不开 | Android 9+ 禁止明文 HTTP | 项目根目录 `AndroidManifest.xml` 加 `android:usesCleartextTraffic="true"` |
| 全部正常但过一会儿断    | 电脑防火墙                | 放行 8000 端口，或临时关防火墙测一次                                               |

**验证网络的最快方式**：手机浏览器打开 `http://电脑IP:8000/docs`，能出接口文档就说明网络通了。

### `adb` 点不动 scroll-view 里的按钮（2026-10-29 踩的）

`adb shell input tap` 在 `scroll-view` **内部**点不动任何元素——按下时间只有几毫秒，
被滚动容器当成滚动手势起点吃掉了。真人点击有 50-100ms 按住时间，所以是好的。

**排查"点了没反应"的第一步**：用截图 + PIL 量出控件的真实坐标（目测裁剪图偏差可达 100px），
确认真的点在控件上；能让人手动点一下确认的，别自己反复 adb 戳。
（曾经因此误判三个点按钮"坏了"，白改三轮还回滚。）

### 编译卡死的恢复

`cli launch` 连续跑可能卡住（只打印版本行、毫无进展）。恢复方式：
`taskkill /IM cli.exe /F` + 重启 HBuilderX，然后用**项目名**而不是路径：

```bash
D:/Dev/HBuilderX/cli.exe launch app-android --project "android" --deviceId <设备号> --playground standard
```

（重启 HBuilderX 后传绝对路径会报「项目类型为Web」，必须用 `--project android`。）

## 七、常见问题

**429 Too Many Requests**
发码有 60 秒频控。测的时候换个手机号，或者等一分钟。

**登录一直失败**
验证码 5 分钟过期。重新发一次，或直接读库：

```bash
python -c "import sqlite3;print(sqlite3.connect('minglu.db').execute('select code from sms_code order by last_sent_at desc limit 1').fetchone())"
```

**对话没有流式效果，一次性出全文**

- 后端：确认用的 `/v1/chat/stream`，不是 `/v1/chat`
- 前端：`api/chat.ts` 里 `enableChunked: true` 是否保留
- 网络：中间有没有代理缓冲（nginx 需关闭 buffering）

**配了模型却没生效 / 回复一直是模板兜底**

按这个顺序查：

1. **系统环境变量覆盖 `.env`** —— `os.getenv` 优先，而 `.env` 由 `config._load_dotenv()`
   在不覆盖已有变量的前提下灌入。某个终端 `export` 过 `LLM_*` 就会压住 `.env`。
   `reg query "HKCU\Environment"` 看是不是永久设进了注册表。
2. **`LLM_BASE_URL` 不在白名单** —— 白名单要求**完整路径前缀**，不是裸域名
   （智谱是 `https://open.bigmodel.cn/api/paas/v4`，方舟 `/api/v3`，百炼 `/compatible-mode/v1`）。
   配错了不报错，只会静默降级。
3. **看启动日志** —— `get_provider()` 每次决策都打 info：`llm provider = openai-compat，model = xxx`。
   打的是 `local-template` 就是没接上。

**思考模型返回空白**

`glm-5.x` / `deepseek-r1` 这类"始终思考"的模型会把预算先花在推理上，`max_tokens`
给小了正文被挤成空 content。provider 会抛错走降级（不会给用户空白气泡）。
主链路已给到 2000；**记忆抽取干脆不传 `max_tokens`**（推理长度不可预测，实测同一条输入
从几百到四千 token 波动）。另外这类模型用 `reasoning_effort: low` 关小思考，
延迟能降一半且人设不丢——健康陪伴场景建议开。

**提醒不响**

- Android 13+ 通知权限（运行时）
- 精确闹钟权限（Android 12+）
- ROM 白名单：vivo 要开「后台高耗电」+「自启动」
- `android/` 还没接 `minglu-alarm` 插件，提醒目前只做 CRUD 不注册本机闹钟
